# 连续到站间隔学习

2026-09-18，保持全离线。站台测得的是本站同一交路的到站间隔，并不代表始发站的官方发车间隔。

## 使用

1. 在具体班次点击“记录”→“连续记录间隔”。确认第一班对应的系统预计班次，实际到站时点击“第一班已到站，开始记录”。
2. 持续观察同一站、同一交路。下一班到站时先确认“没有漏车”，再点击“下一班已到站”；每次成功后确认框重置。
3. 至少三班形成两个间隔，且间隔稳定时才启用学习。关闭窗口、重启应用不会丢失本组，在同一站同交路入口可以继续。
4. 有漏车或离开站台时选择“结束本组”，之后重新开始；不同组之间不构造间隔。误记可删除整组，普通观测不受影响。
5. “用户校准”模式使用学习间隔；“系统预计”继续使用原时刻表。无有效间隔或近期锚点时保留之前的校准方式。

## 逻辑与范围

- `domain/HeadwayLearning.kt` 负责记录校验、统计、预测和验证，Compose 只负责显示和调用。
- 保存到 `UserOverrides.headwaySessions`，按线路隔离，并按站点、交路、日型、时段筛选。零散普通观测、不同组之间的空缺不能推导为间隔。
- 现场追加必须确认无漏车；间隔范围为1～30分钟，一组最长2小时。重复点击、跨日期、设备时间跳变、已结束组均不能追加。
- 学习使用过去90天、同日型、同通勤时段且相距1小时以内的区间。横跨时段边界的间隔不参与。中位数/MAD剔除异常值；至少2个有效间隔，MAD不超过中位数的25%。近期、相近时刻权重更大。
- 以最近两小时的连续观察组最后一班，或确认班次的普通现场观测作为相位锚点，按学到的间隔递推。基础序列与预测时刻都只向锚点之后推30分钟；学习并非完整列车运行图。连续记录已确定班次序号，因此不套用普通偏差的±10分钟限制，而保留学到的真实间隔（总偏移仍保护在两小时内）。用户模式扩大候选序列范围，并按组内已观察到的真实时刻移除过期车辆，避免已到站班次按旧基础时刻重新出现。
- 第一班必须匹配正确，之后用户确认没漏同交路车，才能按连续班次关联基础序列。全程车和区间车分别记录，不能把另一交路的车混进序列。

## 提前预测验证

当已有足够间隔后，每次到站保存时立即冻结下一班的预计时间，存在 `nextExpectedEpochMillis`。下一班记录将这份旧预测复制到点的 `predictedEpochMillis`，而不是使用加入新样本后重新拟合的结果。

窗口展示近30天最多50次已完成间隔预测的平均绝对误差。没有预存预测时不生成成绩；成绩只代表记录过的样本，不等于整条线路的准确率。间隔窗口的“下一班预计”直接来自连续观察，跨高峰时段边界不继续使用旧时段间隔；主列表另有上述外推限制。
