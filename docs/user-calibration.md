# 分时段用户校准与到站锚点

落地日期：2026-09-18。用户数据不会覆盖内置时刻表，也不会把离线推算标成实时信息。主界面提供“系统预计 / 用户校准”选择，用户决定哪一种作为当前主倒计时。

## 渐进学习（当前版本）

已实现“准确记录＋历史与锚点融合＋误差验证”，并加入连续班次的间隔学习，入口和规则见 `docs/headway-learning.md`。有效的间隔学习可在短时范围内接管用户口径预测，其余情况继续使用本页的校准方式。

### 如何记录

- 在具体班次点击“记录”，确认是否确实是该系统预计时刻对应的车；不确定时不勾选，样本降低权重。
- 车实际到站时点击“车已到站”，保存到秒的时刻、日期和所选班次。确认同班后，在实际到站 15 分钟内手动保存的时刻也可作为近期锚点；手动输入不参与提前预测验证。
- 班次初次在完整列表中显示时冻结系统、用户两份预测及其产生时间；记录时不重新用最近班次替换归属。同一班重复现场点击保留首次记录，纠错需先删除再录入。
- 记录窗口显示近90天确认记录数、覆盖天数，以及近30天最多50次可比较预测的平均绝对误差。主倒计时显示本次校准使用的样本数。

### 学习方法

同站、同交路出现带预测快照的新记录后，启用 `domain/CalibrationLearning.kt`；旧记录保留并降低权重参与。仅有旧版记录时仍走下述兼容路径。

- 日型已知时严格隔离工作日/周末，未知日型权重再乘 0.5。
- 只使用过去90天有日期的样本；旧版无时间戳记录按30天前低权重兼容。未来时间戳不参与。
- 相近时刻权重为 `1 / (1 + (时差 / 1800秒)^2)`，近期权重为 `exp(-年龄天数 / 14)`；确认班次权重1，否则0.25。
- 使用加权中位数与MAD过滤孤立偏差，阈值至少60秒。确认班次最大偏差10分钟；不确定及旧记录仍限制5分钟。时刻表已移除原班次时，不再套用其旧偏差。
- 历史平均先根据有效权重总和逐渐生效，再乘信任系数：无足够验证时0.5；同日型、相距1小时内至少5次、覆盖至少2天且校准误差低于系统时0.85；足量验证未改善时0.2。阈值属于保守的初始策略，并非准确率保证。
- 已确认锚点对应的当前班次直接采用实际到站时刻，避免晚到班次仍按系统时间提前消失；锚点对后续班次与历史修正加权融合，影响从0.8在两小时内线性衰减到0。历史不会被单个锚点长期替代。
- 用户模式的班次筛选和排序也采用修正时刻，避免延误班次提前消失或已离站班次滞留。

### 如何验证改善

只统计确认同班、同日期、同日型、现场点击到站且预测至少提前30秒产生的记录；必须同时存在两份冻结预测。补录、首次尚无校准预测、事后预测和重复点击不能生成对比成绩。误差按 `abs(预测时刻 - 实际时刻)` 计算，不使用刚加入训练后的结果。样本不足时显示“暂不判断改善”。

当前只保存用户实际记录的班次，不是后台持续验证；结果反映这些样本，不能保证每增加一条都更准，也不代表整条线路。

## 仅有旧记录时的分组和回退

每条新观测除站点、交路和实际到站时刻外，还记录运营日类型、通勤时段、保存时间戳和保存时的本地当天秒数。

- 早高峰：07:00（含）至 10:00（不含）。
- 晚高峰：17:00（含）至 20:00（不含）。
- 其余时间：平峰。
- 工作日与周末分别统计。

用户校准按以下优先级选择：

1. 两小时内有效的近期现场锚点；
2. 当前运营日类型、当前通勤时段的平均，至少 2 条有效样本；
3. 当前运营日类型的全天平均，至少 2 条有效样本；
4. 全部历史有效样本的平均，用于少量样本和旧版数据回退。

每条观测先与它所属运营日类型的最近一班基础时刻匹配，再计算有符号偏差。偏差绝对值超过 5 分钟仍按原规则剔除。旧版观测没有运营日和时段元数据，会保留并参与第 4 级回退，不会因升级丢失。

## 旧版近期到站锚点（兼容路径）

用户在“记录实际到站时间”弹窗用接近当前时刻的值保存后，这条记录成为同站、同交路的近期锚点。锚点偏差会递推到该交路后续班次的用户口径时间；选择“用户校准”后，它会成为主倒计时。

锚点约束：

- 只作用于同一站和同一交路，不把全程车偏差套到区间车；
- 只作用于锚点对应班次及其后的班次；
- 只在相同运营日类型下生效；
- 保存动作与所填到站时刻相差不超过 15 分钟，避免补录旧数据误作现场锚点；
- 保存后有效 2 小时，最新有效锚点优先；过期后仍作为普通历史样本参与分组平均；
- 时间戳来自未来或缺少元数据时不启用锚点。

基础预计的 `arrivalSecondsOfDay` 和来源标志保持不变。用户口径通过 `userArrivalSecondsOfDay` 单独计算，界面显示“用户近期锚点 / 用户早高峰校准 / 用户工作日平均 / 用户全天平均”等来源。

## 显示口径切换

- “系统预计”是缺省口径，只显示内置离线时刻表的推算结果。
- “用户校准”优先采用当前站点、线路、交路和时段适用的锚点或历史平均，主倒计时和到站时刻一起切换。
- 当前班次没有适用的用户数据时继续显示系统结果，并标注“暂无用户校准，已使用系统预计”。不同线路或交路的样本不能互相套用。
- 该选择同时作用于完整站点页和“我的订阅”，保存在 `metro_settings / arrival_display_mode`，应用重启后保持。

## 持久化兼容

`ArrivalObservation` 的所有新字段均有缺省值，旧的 `user_overrides.json` 可直接解析。新记录另存 `observedSecondsOfDay`、`observedEpochMillis`、`observationDate`、`prediction`、`matchConfirmed`、`liveArrival`。快照保存系统与校准秒数、预测时间戳、日期和日型。

同一文件的 `otherLines` 保存其他线路的独立修正，内部条目不再嵌套。切换线路录入不会覆盖原线路记录；读取、删除、区间车和其他修正都按线路隔离。旧的单线路文件在后续保存时自动兼容。升级前已经被旧版覆盖的记录无法凭空恢复。

## 验证

原有273个用例保持通过；后续用例覆盖明确班次、重复记录、权重衰减、异常值、历史与锚点融合、提前预测验证、确认秒级记录、持久化兼容、跨线路累积以及校准后班次筛选。当前全量360个用例通过，debug APK 构建通过。真实准确度需后续现场记录验证，单元测试验证算法行为而非实地准确率。

模拟器实测：确认班次后秒级记录、用户模式融合倒计时、重启保留、记录窗口的冻结预测误差及样本不足提示、重复现场点击不增样本、2号线新增记录后1号线旧观测仍保留。模拟数据用于验证流程，不作为准确率证据；验证结束后恢复原用户文件和设置并核对哈希。
