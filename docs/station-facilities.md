# 出入口与站内设施（第二阶段第一项）

## 已确认范围与入口

本轮只推进“出入口与站内设施”。首页选站后点击“出入口与设施 · 我的车站备注”，
或在收藏卡点击“出入口与设施”。不增加底栏入口，返回时保留原来的首页/收藏位置。

详情页包括：
- 官方资料按线路分别展示：已收录出口说明、卫生间、无障碍卫生间、坡道、升降平台、直梯等。
- 来源标题、官网链接、原页面更新时间和本次资料核对日期。
- 个人备注：常走出口/周边地标、设施位置、换乘提示；可编辑或二次确认后清除本站备注。
- 未覆盖的车站/线路明确显示“暂未收录”，不将缺失资料解释为没有设施。

本批不包含出口经纬度，不能计算最近出口、步行距离或生成无障碍通行路线。
未收录换乘通道的现场路径，用户可以先保存自己的换乘备注。
官网链接由外部浏览器打开（需要网络）；App 日常使用仍全离线，不新增 INTERNET 权限。

## 数据与扩展

- 内置资料：app/src/main/assets/metro/station_facilities_beijing.json，UTF-8 无 BOM。
- 模型：data/model/StationFacilities.kt。按 stationKey + lineId 唯一，换乘站不同线路不混用。
- stationKey 复用 OfflineRoutePlanner.stationKey，包含城市标识，避免跨城市同名站串用。
- 个人备注：SharedPreferences(metro_settings) 中独立键 station_personal_notes，
  不修改内置 JSON、原收藏、行程或旧时刻数据。每项最多 1000 字。
- domain/StationFacilityPolicy.kt：线路匹配、备注校验、更新与删除。
- data/StationFacilityCodec.kt：纯 JVM 解析；损坏的备注不能被默认为空列表后覆盖。
- data/source/StationFacilityStore.kt：Android 资源与持久化胶水，读写在 IO 线程完成。
- ui/StationDetailsScreen.kt：展示与编辑，沿用 8dp 线路色条。

新增资料时必须有可核对的来源、原始更新日期和范围说明。没有来源的字段保持缺失。
新增城市不应复制北京车站资料；用户备注与官方资料不得自动合并为“官方”信息。

## 验证

新增逻辑与资料完整性测试覆盖城市/线路隔离、车站后缀匹配、备注限长、局部更新/删除、
中文编解码、损坏数据保护、格式版本及内置资料对应真实站点与官方来源。
